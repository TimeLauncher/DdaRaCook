# 백업 백엔드 · 체인 메모

측정일: 2026-08-26

## 왜 만들었나

NVIDIA NIM(`nvidia/nemotron-nano-12b-v2-vl`)이 두 가지로 고장난다.

| 고장 모드 | 증상 | 실측 |
|---|---|---|
| 즉시거절 | HTTP 500 `EngineCore encountered an issue` | **1초 안에** 실패. 21쌍 중 20쌍이 이렇게 실패한 회차가 있었다 |
| 지연 | 같은 입력에 응답 시간이 튐 | 4.2 / 4.6 / 35.5 / 11.1 / 7.5초 (연속 5회, **동일 바이트**) |

동일 입력에서 8배 편차가 났으므로 원인은 우리 데이터가 아니다. 크롭·프롬프트·
사진 난이도는 모두 배제됐다(아래 "배제된 가설").

## 배제된 가설

| 의심 | 검증 방법 | 결과 |
|---|---|---|
| 데이터 양(271KB) | 148KB·136KB와 라운드로빈 8회 | 현행 271KB가 8/8 성공, 최대 5.2초로 **가장 안정적** |
| 사진 장수(2장) | 1장 전송과 비교 | 1장이 더 나빴다. 45초 타임아웃도 1장 쪽 |
| 프롬프트 | 모든 호출에서 동일 | 변동을 설명할 수 없음 |
| 사진의 애매함 | 출력 토큰 상한 분석 | 출력이 **23tok**, 상한 200tok. 30초짜리 정지를 만들 수 없음 |
| 우리 서버·YOLO | 성공 호출 왕복 3,295ms 분해 | 서버 411ms, 폰 YOLO 70ms |
| Render 콜드 스타트 | 깨운 뒤 재시도 | 여전히 발생 |

## 백엔드 선정 (2026-08-26 최종)

무료 티어만 검토했다(예산 없음).

**NVIDIA 내부 다른 모델 — 부적합.**
`meta/llama-3.2-11b/90b-vision-instruct`는 `At most 1 image(s) may be provided`로
2장 비교가 불가능하다(CONTRACT §3.2 위반). `microsoft/phi-3-vision-128k-instruct`는
404. 살아남은 `nvidia/llama-3.1-nemotron-nano-vl-8b-v1`은 첫 시도에서 오답이었다.
무엇보다 **같은 엔드포인트라 함께 죽는다** — 실제로 `nemotron-nano-8b-v1`도 같이
타임아웃했다.

**Groq — 1차 백업으로 채택.**

- 모델: `qwen/qwen3.6-27b` (2026-08 기준 무료 티어에서 이미지를 받는 유일한 모델)
- 지연: **470~1,323ms** — NVIDIA 정상 시(3,236ms)보다도 빠르다
- 다른 회사라 **장애 영역이 독립적**이다. 이게 핵심이고 NVIDIA 내부 모델로는 못 얻는다

### 반드시 `reasoning_effort=none`

추론 모델이라 그냥 부르면 `<think>`로 max_tokens 200을 전부 쓰고 **정작 JSON을
못 낸다**(실측: 출력 200tok 전부 추론 → `coerce_verdict` parsed=False →
CANNOT_TELL). `none`을 보내면 출력이 16~23tok으로 떨어지고 정상 파싱된다.
`reasoning_effort`는 `none` 또는 `default`만 받는다(`low`는 400).

### 한도 — 분당 토큰(TPM)이 병목

```
x-ratelimit-limit-requests   1000   (4분 19초 리셋)
x-ratelimit-limit-tokens     8000   (25.9초 리셋)   ← 병목
```

판정 1회가 **2장 3,242tok / 1장 1,930tok**이므로 분당 2.5~4회가 상한이다.

> ⚠️ **해상도를 줄여도 토큰이 줄지 않는다.** 768이든 384든 입력이 3,242tok으로
> 동일했다. Groq는 이미지를 고정 비용으로 토큰화하며, 토큰은 해상도가 아니라
> **장수**에 비례한다. 즉 `ROI_OUTPUT_LONG_EDGE` 축소는 NVIDIA 지연 대책이지
> 무료 한도 대책이 아니다.

이 한도 때문에 Groq는 **백업으로만** 쓴다. 주 백엔드가 헤지 시점 전에 답하면
백업 호출이 아예 나가지 않으므로, 평상시에는 할당량을 쓰지 않는다.
NVIDIA가 장기간 죽으면 Groq도 한도에 걸리므로, 그때는 Gemini
(`aistudio.google.com`, 분당 한도가 더 넉넉함)를 체인에 추가한다.

## 체인 설계 (`judge/chain.py`)

```
t=0.0s   주 백엔드(NVIDIA) 발사
t≈1.0s   500이 오면 → 즉시 백업 발사 (예산 6.5초 남음)
t=2.5s   응답이 없으면 → 백업 동시 발사 (헤지)
t≈3.2s   먼저 온 답 채택
t=7.5s   둘 다 실패해야 503
```

- 정상일 때 백업을 부르지 않는다 → 무료 한도 절약 (`test_chain.py` 로 고정)
- 전부 실패하면 `CANNOT_TELL`이 아니라 예외를 올린다 (CONTRACT §5)
- 어느 백엔드가 답했는지 `Verdict.backend`에 실려 응답·로그에 남는다
- `/health`의 `describe()`에 백엔드별 win/fail/calls 통계가 나온다

## 해상도 축소

`ROI_OUTPUT_LONG_EDGE` 768 → 512. NVIDIA 라운드로빈 실측에서
p50 3,236ms → 2,266ms(약 1초 단축). 서버와 앱 두 곳의 상수를 **같이** 바꿔야 한다.

- `server/roi_cropper.py:ROI_OUTPUT_LONG_EDGE` (환경변수로 조절 가능)
- `app/.../OnDeviceRoiCropper.kt:ROI_OUTPUT_LONG_EDGE`

다르면 폰 YOLO 실패로 서버 크롭에 폴백할 때 같은 단계인데 판정 입력 크기가 달라진다.


## 21쌍 정확도 비교 (768, 같은 프롬프트)

| 백엔드 | 정확도 | false accept | p50 | 호출실패 | 처리량 |
|---|---:|---:|---:|---:|---|
| **gemini-flash-lite-latest** | **19/21 (90%)** | 2 | 1,737ms | 0 | 21회 연속 무제한 (분당 ~31회) |
| qwen/qwen3.6-27b (Groq) | 16/21 (76%)* | 3 | 645ms | 0 | 분당 2.4~4.1회 (8,000 TPM) |
| nemotron-nano-12b (NVIDIA) | **측정 불가** | — | 3,236ms | 다수 | — |

*Groq 수치는 384 기준. 768 재측정은 TPM 때문에 오래 걸려 중단했고, 6쌍까지는
384와 동일한 패턴이었다(4/6, 틀린 쌍도 같음).

NVIDIA 는 21쌍을 **한 번도 완주하지 못했다.** 8쌍째에서 재시도 6회를 소진했다.

### 최종 순서: `JUDGE_CHAIN=gemini,groq,nemotron`

- **Gemini 주** — 정확도가 결정적(90% vs 76%). 1.7초로 3초 목표 안에 들고
  한도 여유가 15배라 주력으로 감당된다.
- **Groq 1차 백업** — 645ms 로 가장 빠르므로 헤지가 걸렸을 때 즉시 메꾼다.
  한도가 빠듯한 건 백업으로만 쓰면 문제되지 않는다.
- **NVIDIA 최후** — 버리지는 않되 의존을 끊는다.

`JUDGE_HEDGE_AFTER_S=3.0` — Gemini 관측 최대가 2.4초이므로 정상일 때는 헤지가
나가지 않는다. 실측 확인: 3회 요청에 **헤지 0회**, 백업 호출 0회.

> ⚠️ Gemini 모델 선택 주의 — `gemini-2.5-flash` · `gemini-3.5-flash` ·
> `gemini-3.6-flash` 는 추론 모델이라 max_tokens 200 을 생각에 다 쓰고
> `CANNOT_TELL parsed=False` 로 떨어진다(7~8tok 출력, 7~17초). Groq qwen 과 같은
> 함정이다. **`flash-lite`** 는 추론을 안 해서 깔끔하게 JSON 을 낸다.

## 해상도는 768 유지

512 로 낮췄다가 되돌렸다. 512 는 NVIDIA 지연 대책이었는데 주 백엔드가 바뀌며
근거가 사라졌고, 정확도 측정이 전부 768 기준이다. NVIDIA 7쌍 비교에서도
512 가 768 보다 나빴다(4/7 vs 5/7, 512 에서만 false accept 1건).
Groq 는 해상도와 무관하게 토큰이 고정이라 512 로 얻는 한도 이득도 없다.

## 남은 숙제 — 라벨 의심

`soya_pan_missing_sausage_01` 은 **Gemini · Groq · NVIDIA 512 · NVIDIA 768
네 조건 전부**가 `DONE` 이라고 한다. 라벨은 `NOT_DONE` 이다. 네 모델이 똑같이
틀리는 것은 모델 문제라기보다 라벨이나 완료 조건 문구가 사진과 맞지 않을
가능성이 크다. 사진을 직접 확인해 볼 것. 이 한 건이 라벨 오류라면 Gemini 는
20/21(95%)이 된다.

false accept 2건은 `CONTRACT §12` 의 "잘못된 자동 진행 0회" 와 충돌하므로,
라벨 확인 후에도 남으면 프롬프트나 보수적 편향으로 따로 다뤄야 한다.
