## 1. 기술 스택 결정

| 항목 | 결정 | 비고 |
|---|---|---|
| 언어 | **Python** | 평가 스크립트 작성이 압도적으로 편함 |
| 웹 프레임워크 | **FastAPI** | 엔드포인트 1개짜리에 적합 |
| 1순위 VLM | **NVIDIA Nemotron** (무료) | 비용 0, 실험 우선 |
| 2순위 VLM | **OpenAI (ChatGPT API)** | Nemotron 미달 시 전환 |

| 배포 | Render / Railway / Fly.io 중 택1 | 무료 티어 |

### 왜 어댑터 구조인가

벤더 종속 코드를 `judge/` 폴더 안에만 가둔다. 서버 본체·평가 스크립트·테스트 데이터·프롬프트는 벤더와 무관하게 재사용된다.

```
server/
├── judge/
│   ├── base.py         # 규격(Protocol) + Verdict 타입 + JSON 파서
│   ├── nemotron.py     # 1순위 구현
│   └── openai.py       # 2순위 구현 (조건부)
├── prompts.py          # 프롬프트 (벤더 무관)
├── server.py           # FastAPI (벤더 코드 없음)
├── probe.py            # 사전 검증 스크립트
├── eval.py             # 정확도 평가
└── testdata/
    ├── images/
    └── labels.json
```

전환은 환경변수 한 줄:
```bash
VLM_BACKEND=nemotron uvicorn server:app     # 기본
VLM_BACKEND=openai   uvicorn server:app     # 전환
```

**이 구조는 "교체 보험"이 아니라 그 자체가 산출물 C(모델 선정 근거)를 만드는 수단이다.** 두 백엔드를 같은 테스트 세트로 돌려 비교표를 뽑는 것이 3번의 핵심 업무다.

- [x] `Verdict` 데이터 타입

- [x] **관대한 JSON 파서** `coerce_verdict(text)`

**파서 요구사항**
- ` ```json ... ``` ` 로 감싸진 경우 처리
- 앞뒤에 설명 문장이 붙은 경우 JSON만 추출
- 파싱 실패 시 **반드시 `CANNOT_TELL`** 반환 (절대 `DONE`으로 떨어지지 않게)
- `verdict` 값이 3종 외의 문자열이면 `CANNOT_TELL`

> **왜 관대한 파서가 필요한가**: 오픈 모델은 JSON 형식을 보장하지 않는다. 명세서 목표가 "잘못된 자동 진행 0회"이므로, 못 읽었을 때 안전한 쪽(`CANNOT_TELL`)으로 떨어지는 것이 설계상 중요하다.

**DoD**: 파서 단위 테스트 5케이스 통과 (정상 / 코드블록 / 설명 포함 / 깨진 JSON / 이상한 verdict 값)

#### T2-8. 🔬 공개 데이터셋으로 **개발셋** 확보 (타임박스 6시간)
**예상 6시간 (엄수) · 선행 T2-2 · T2-3의 선행이 아니라 가속기**

> 🚨 **왜 이걸 하는가 — T2-3의 8시간이 통째로 헛돌 위험이 있다.**
>
> T2-1 데모 세트(23쌍)로 잰 A등급 정확도 85.7%의 **95% 신뢰구간이 [48.7%, 97.4%]**,
> 폭이 49%p다. 참값이 50%인지 97%인지 구분이 안 된다.
> **이 상태로는 프롬프트 v1→v2가 나아졌는지 판정할 수 없다.**
>
> | 원하는 정밀도 | 필요한 n |
> |---|---|
> | ±20%p | 13 |
> | ±15%p | 21 |
> | **±10%p** | **48** |
> | ±5%p | 195 |
>
> 안경으로 195쌍은 비현실적이다(T2-1이 20~30쌍에 7시간). 그런데 T2-3에서 보려는
> 프롬프트 간 차이는 대개 한 자릿수 %p다. **잴 수 있는 자가 없는 채로 8시간을 쓰게 된다.**

**역할 분리** — 이 태스크가 만드는 건 검증셋이 아니라 **숫돌**이다.

| | 안경 세트 (T2-1) | 개발셋 (T2-8) |
|---|---|---|
| 역할 | **보고용 숫자** — DoD 판정, 시연 근거 | **개발용** — 프롬프트 반복 |
| 크기 | 20~30쌍 | 200장 이상 |
| 사용 빈도 | 마일스톤에만 | 수십 번 |
| 라벨 출처 | 촬영자가 그 자리에서 기록 | 행동 분절 경계에서 역산 |

> 💡 **왜 유튜브 수동 수집보다 공개 데이터셋이 먼저인가**
> `Epic-Kitchens` · `Ego4D` 는 **머리 장착 카메라 1인칭**이다. 손이 프레임에 계속
> 들어오고 대상이 프레임을 벗어나는, **안경과 같은 계열의 화각**이다.
> 유튜브 요리영상은 편집자가 보기 좋게 찍은 3인칭이라 가림·프레임 이탈이 거의 없고,
> 그래서 **CANNOT_TELL 표본을 만들지 못한다.** 게다가 시간 주석이 이미 붙어 있다.

**핵심 아이디어 — 행동 분절의 끝 경계 = 완료 시점**

이 데이터셋들이 주석한 건 *행동*("fry onion")이지 *상태*("익었는가")가 아니다.
그대로는 못 쓰지만 변환이 된다.

```
[      fry onion 구간      ]
 ↑          ↑             ↑
시작       중간           끝
NOT_DONE  NOT_DONE      DONE
```

T2-1에서 손으로 만든 라벨 구조와 **같다.** 끝점 하나를 알려주고 나머지를 역산했던
그 방식이고, 데이터셋에는 그 경계가 이미 초 단위로 찍혀 있다.

---

**진행 순서 — 싼 것부터. 순서를 틀리면 하루가 날아간다.**

- [ ] **Step 0 (10분)** `Ego4D` 이용 동의부터 신청 — 승인 대기를 나머지 작업과 겹친다
- [ ] **Step 1 (1h)** 접근 조건 실사, **다운로드 없이**
      → 라이선스 / 접근 절차 / 용량 / 주석 포맷을 `notes/datasets.md` 비교표로
      → **🚧 게이트 A**: 접근 가능한 게 하나도 없으면 → 유튜브 수동 수집으로 후퇴
- [ ] **Step 2 (1.5h)** **주석 파일만** 받아 변환 가능성 확인 — 영상은 아직 안 받는다
      → 주석은 수 MB, 영상은 수십~수백 GB다. **이 순서를 지키는 게 이 태스크의 핵심**
      → 확인할 것: ① 상태 변화형 행동(볶기·끓이기·굽기)이 몇 건인가
        ② 분절에 시작·끝 타임스탬프가 있는가 ③ 우리 `checkType` 5종에 매핑되는가
      → **🚧 게이트 B**: 상태 변화형 분절이 200건 미만이면 규모 이점이 없다 → 중단
- [ ] **Step 3 (1.5h)** 소량 실물 검증 — 영상 3~5개만 받아 프레임 20~30장
      → ★ **사람 눈으로 확인**: "완료"로 뽑은 프레임이 정말 완료로 보이는가
      → **🚧 게이트 C**: 여기가 이 계획 전체의 가정이다. 깨지면 나머지는 전부 무의미하니
        **미련 없이 폐기**하고 T2-3은 안경 세트로 진행한다
- [ ] **Step 4 (1.5h)** 파이프라인 — **`eval.py` 를 고치지 않는다**
      → 영상+주석 → 프레임 → `manifest.json` + `labels.json` 을 **같은 형식으로** 생성
      → `testdata/dev/` 로 분리하고 `.gitignore` 에 넣는다 (저작권·용량)
- [ ] **Step 5 (0.5h)** 기준선 1회 실행 + 안경 세트 숫자와 나란히 기록

**DoD**: 개발셋 200장 이상이 `eval.py --labels testdata/dev/labels.json` 으로 돌아가고,
`notes/datasets.md` 에 라이선스·주석 포맷·변환 규칙이 기록됨

---

> 🚨 **진짜 합격 기준은 "크다"가 아니라 "같은 방향을 가리킨다"이다.**
>
> 개발셋이 아무리 커도, 거기서 v2가 좋아졌는데 안경 세트에서 나빠지면 **쓸모가 없다.**
> 오히려 잘못된 방향으로 8시간을 쓰게 만든다.
>
> **그래서 T2-3의 첫 프롬프트 개선 때 두 세트를 함께 돌려 방향이 일치하는지 확인한다.**
> 어긋나면 개발셋을 폐기한다. 이 확인 전까지 개발셋 숫자를 어디에도 보고하지 않는다.

**주의 — 개발셋 과적합**

같은 개발셋을 보며 프롬프트를 계속 고치면 그 데이터에만 잘 듣는 프롬프트가 나온다.
가중치를 안 건드려도 과적합은 일어난다. **안경 세트를 아껴 쓸수록** 그 숫자가
시연을 예측하는 힘이 커진다 → 마일스톤에만 돌린다.

**주의 — 라이선스**

`Epic-Kitchens` 는 비상업 연구용 조건, `Ego4D` 는 별도 이용 동의, `YouCook2` 는
영상 ID만 제공(다운로드는 각자)인 것으로 알고 있으나 **Step 1에서 실제 확인이 필요하다.**
내부 평가와 **발표자료 게재는 별개 문제**다. 프레임을 슬라이드에 싣기 전에 확인할 것.

**실패해도 일정이 안 밀리는 이유**

이 태스크는 T2-3의 **선행이 아니다.** 게이트 A·B·C 어디서 끊겨도 T2-3은 안경 세트로
그대로 진행된다. 잃는 건 정밀도이지 진행이 아니다.
