# 우삼겹 파스타 — 두 번째 자동 확인 레시피

상태: `DEVICE_VERIFIED_EVAL_PENDING` · 병렬 타이머 F-ID 신설 필요

출처는 유튜브 [자취요리신 simple cooking · 「너무 쉬운 자취요리 끝판왕 등장했습니다」](https://youtu.be/SSbyRvzf1VQ)(0:54, 2025-10-17)이고,
설명란 원문 4단계를 앱 6단계로 옮겼다. 데이터 정본은 `RecipeFixtures.kt`의 `beef-brisket-pasta`.

## 재료

우삼겹 200g · 대파 1대 · 스파게티면 1인분 · 깻잎 3장
양념: 다진마늘 1/2큰술 · 설탕 1/2큰술 · 진간장 1큰술 · 굴소스 1큰술 · 후추 약간

> 원문은 "스푼"으로 적혀 있다. 쏘야 재료 표기와 맞춰 **큰술**로 옮겼다.
> 원문의 **냉동** 스파게티면은 이미 삶아 얼린 제품이라 팬에 바로 들어가지만, 일반 면으로 바꾸면서
> 삶는 과정이 1단계로 들어왔다. 삶는 시간 8분은 원문에 없는 값이고 3번이 정했다.

## 왜 이렇게 갈랐나

- **원문 1단계를 손질과 볶기로 쪼갰다.** 원문은 "우삼겹과 대파를 다 같이 볶는다"로 시작하는데,
  그러면 세션의 첫 판정이 곧바로 팬 위 색상 변화가 된다. 쏘야에서 검증된 도마 위 절대 판정
  ("통째로 남은 …이 없는가")을 첫 자동 판정으로 두어 첫 판정 실패가 바로 수동 모드로 떨어지는 길을 막았다.
- **3·5단계가 이 레시피의 두 축이고 둘 다 색상 변화(B)다.** 고기가 익는 것도, 면에 양념이 배는 것도
  "무엇이 있는가"가 아니라 "색이 변했는가"라서, 존재 판정으로는 넣자마자 참이 되어 볶는 과정을
  전혀 담지 못한다. 대신 §5.1의 **"B등급은 1개 단계만"과 어긋난다** — 아래 미합의 항목.
- **4단계만 연속 DONE 2회가 필요한 이유가 다르다.** 존재 판정은 양념을 붓는 즉시 참이 되므로,
  검사 간격이 런타임에서 30초로 덮이는 것을 이용해 2회를 요구해 최소 30초의 볶는 시간을 만든다.
  3·5단계의 2회는 색 변화 오탐을 거르기 위한 것이다.
- **원문에 시간이 없다.** `maxExpectedSeconds`(3·5단계 각 240초·180초)는 원문 인용이 아니라
  우삼겹 두께와 면에 양념이 배는 시간을 잡은 값이다. 2회차 촬영에서 실측해 고친다.
- **`isMvpReady = false`.** 자동 확인 배선은 끝났지만 이 요리로는 촬영·라벨링을 하지 않아
  정확도를 측정한 적이 없다. 시연 대표는 쏘야 한 종(F1-5)으로 유지한다.

## 1단계는 병렬 타이머다 — 새로 만든 기능

의도한 동작은 **면을 넣고 타이머를 건 채 2단계로 넘어가, 조리 중 8분이 차면 "면을 건지세요"가
울리는 것**이다. 기존 시계(`stepElapsedSeconds`)는 단계가 바뀌면 리셋되므로 쓸 수 없어서
`RecipeStep.parallelTimer`를 새로 넣었다.

| 파일 | 변경 |
|---|---|
| `RecipeModels.kt` | `ParallelTimer(label · durationSeconds · doneAnnouncement)` · `RecipeStep.parallelTimer` · 검증 |
| `CookingSessionStateMachine.kt` | `CookingSession`에 만료 **시각**·이름·문구·발화 여부 · `parallelTimerRemainingSeconds()` |
| `CookingSessionViewModel.kt` | `startStep`에서 타이머 걸기 · 티커가 만료를 감시해 `announceParallelTimerDone()` |
| `AppPersistence.kt` | 레시피 단계와 세션 양쪽 직렬화 |
| `MainActivity.kt` | 조리 화면 남은 시간 배너 · 편집기가 기존 타이머를 지우지 않도록 보존 |

설계에서 정한 것:

- **남은 시간이 아니라 만료 시각을 저장한다.** 앱을 껐다 켜도 냄비는 계속 끓는다. 복귀 시점에
  이미 지났으면 그 자리에서 바로 안내가 나간다.
- **발화는 1회.** `parallelTimerFired`로 막는다. 1초마다 도는 티커가 같은 말을 반복하면 안 된다.
- **세션이 끝난 뒤에는 울리지 않는다**(`SESSION_COMPLETED` 제외).
- **같은 단계를 다시 시작하면 타이머도 다시 건다.** "이전" 명령으로 1단계로 돌아가는 건 냄비를
  다시 앉히는 것이기 때문이다.
- **수동 모드 화면(S8)에는 남은 시간 배너가 없다.** 안내 발화는 그대로 나간다.

기능명세서에 해당 기능 ID가 없다. 신설이 필요하다.

## 남은 것

- **병렬 타이머는 2번 영역(상태 머신·화면·저장)을 건드렸다.** 3번 승인으로 진행했고, 2번에게는
  동의를 받는 게 아니라 **알린다**. 기능명세서 F-ID 신설은 아직 남아 있다
- 🚧 **자동 판정 3개 중 B등급이 2개다.** §5.1은 "A등급 중심 · B등급 1개 단계만"인데 3·5단계가 모두
  색상 변화다. 쏘야와 같은 종류의 미달이며(쏘야는 3개 전부 B), 2회차 평가에서 B등급 색상 변화의
  정확도를 재고 결정한다. 미달이면 5단계를 존재 판정("팬 안에 스파게티면이 들어가 있는가", A등급)으로 되돌린다
- ~~`checkType`·단계 수·`InspectionPolicy`는 2번 허가 필요~~ — 레시피 정의는 3번이 정한다(AGENTS 경계표)
- ~~기능명세서 §5.1.2로 위 표를 옮길지~~ — 불필요해졌다. 명세서 §5.1.1의 "완료 조건 문장의 정본"은
  **대표 레시피에 한한다**로 완화됐고, 그 밖의 레시피는 `RecipeFixtures.kt`가 정본이며 근거는 이 문서다
- ~~`CURRENT_FIXTURE_VERSION` 확인~~ — 위 기기 확인에서 끝냈다

> 참고: `totalDurationLabel`은 단계 `maxExpectedSeconds`의 **합**이다. 1단계의 8분은 병렬로 흐르므로
> 단계 자체의 `maxExpectedSeconds`는 면을 넣는 시간 60초로 두었다 — 합계 15분으로, 실제와 거의 맞는다.
